# ProofFlow

An AI agent that converts a legacy workflow (Nintex-style XML) to modern JSON flow logic, then proves the result behaves the same: it generates test scenarios, runs them on both versions, scores the match, repairs failures, and flags what it cannot convert.

## Run locally (VS Code)

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate        macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # Windows: copy .env.example .env
uvicorn app.main:app --reload
```
Open http://localhost:8000.

- No `ANTHROPIC_API_KEY`: ChromaDB retrieves mapping candidates and a keyword scorer decides.
- With a key in `.env`: unknown actions are mapped by the Claude API (forced JSON schema via tool use) using the retrieved context. Set `PROOFFLOW_MODEL` if your key needs a different model name.
- The first run downloads Chroma's small embedding model, so it needs internet once. `PROOFFLOW_OFFLINE=1` skips Chroma and the LLM.

## Demo order (matches the official demonstration)
1. Click **Load sample** (or upload any workflow `.xml`).
2. Click **Run ProofFlow**. Watch the diagram, the conversion, the 20 scenarios, the planted bugs being caught (steps shown red), the repair rounds (60% → 80% → 100%), and the manual-review steps (amber).
3. Read section 6, the checklist: each official step with its input, actual result and evidence. Click **Download run evidence (JSON)**; the same file is saved in `runs/`.
4. MCP proof: in a second terminal run `python mcp_demo.py`. It starts the MCP server, lists the tools, and calls `proofflow_test`, `proofflow_convert` and `proofflow_verify` (clean, then with planted bugs). Evidence goes to `evidence/mcp_verify_evidence.json`. Run ProofFlow again and step 8 of the checklist turns from pending to pass.
5. For a live assistant demo, add the server to Claude Desktop (`claude_desktop_config.json`) and ask it to convert and verify a workflow:
```json
{"mcpServers": {"proofflow": {"command": "/path/to/.venv/bin/python", "args": ["-m", "app.mcp_server"], "cwd": "/path/to/proofflow"}}}
```

## Layout
- `app/core.py` parser, rule converter, simulator, scenario generator, verifier
- `app/mapper.py` RAG (ChromaDB) + LLM mapper for unknown actions; `app/kb.json` mapping knowledge base
- `app/pipeline.py` LangGraph agent loop
- `app/evidence.py` labelled run record (input, expected, actual, evidence)
- `app/main.py` FastAPI API and page; `app/mcp_server.py` MCP tools; `mcp_demo.py` MCP client
- `static/index.html` front end

## Honest scope and limits
- Handles SetVariable, RequestApproval, SendEmail and nested Condition. Other actions go to the mapper and are flagged for manual review below 0.8 confidence, and excluded from the score.
- The simulator is a small interpreter, not the real Nintex or Power Automate engine.
- "Plant bugs" is a demo switch: it makes the first-pass converter wrong on purpose (a misrouted rejection email and a `>` turned into `≥`). Repair re-applies the correct rule to the failing step; it does not use an LLM to patch code.
- Scenarios are generated by rules from the workflow's own conditions, not by an LLM.
- `kb.json` holds 6 sample mappings written from general knowledge. Add real mappings from the Nintex and Power Automate docs for a credible RAG.
- The "escalate after N days" case is modelled as a no-reply (timeout) scenario, not a real timer.
